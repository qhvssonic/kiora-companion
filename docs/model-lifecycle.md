# 聊天模型生命周期与页面导航

0.1.109 修复从设置返回时聊天模型重复加载的问题。

## 原因

旧逻辑在任一 A2A 连接不可用时，从设置返回就调用 `configure()`，即使配置没有改变。
`configure()` 会关闭现有 LiteRT-LM/MNN 模型并重新 `prepare()`，把远端重试变成一次本机模型重载。
真机旧版日志在同一进程内出现多次 `operation=chat-load`，不是每次都由进程重建引起。

## 当前行为

- 不修改配置直接返回设置，保持已就绪状态；不会因远端不可用自动重试全部配置。
- 明确保存设置且有未连接的 A2A 对端时仍可重试发现；远端连接/上下文预算变更可重建工具和运行时，复用原聊天模型。
- 真正改变模型路径、LiteRT CPU/GPU 后端、在线端点/模型/凭据时，先释放旧实例，再加载新实例，不缓存多套聊天权重。
- 本地模型文件的路径、大小和修改时间参与实例身份，避免相同路径下替换文件后继续误用旧实例。
  这不是内容哈希；MNN 目录导入应继续使用现有的独立导入目录，而不是在外部原地修改权重。
- 相同配置重复请求不会再次准备模型。原来已经加载的模型不会因工具配置失败而被错误关闭；新模型配置失败时会清理新实例。
- 取消加载时，若原生加载器仍返回了实例，会释放该实例，不把已取消的模型发布为就绪。

`ModelResourceSlot` 属于 `CompanionAgent`，访问由原有 `sendLock` 串行化。
它没有持有全局 Activity，也不增加后台服务。`MainActivity.onStop()` 仍停止录音和朗读；
聊天模型在 Activity 销毁/Agent 关闭时释放。系统回收进程、销毁聊天页或真正切换模型后，重新加载仍是预期行为。
仅改变页面不会延长旧 Activity 销毁后的模型生命周期。

## 验证

72 项 Companion JVM 测试通过。新增测试覆盖重复获取同一实例、替换时先关闭旧实例、加载失败后重试、
取消原生加载后的清理、本地与在线模型身份所需的字段。

2026-11-03 在 V2509A / Android 16 上覆盖安装 0.1.109（versionCode 110）。导航设备回归
`OK (1 test)`，耗时 32.569 秒；各步骤断言复用同一准备好的模型对象。
该测试进程的 `KioraInference` 日志仅有一次 `operation=chat-load phase=STARTED`，对应初始加载。
测试完成后恢复了原上下文设置，没有发送聊天或远端任务。
此结果只覆盖该手机当前选中的本机模型，不代表已实测 MNN、GPU 或进程重建后的热恢复。

`ChatNavigationDeviceTest` 为显式启用的设备回归，参数 `modelNavigation=true`。
它使用已经导入并选中的本机模型，覆盖设置往返两次、人脸页、相册页、前后台返回及上下文设置变更，
检查准备好的模型对象未变。测试不发送聊天消息或远端任务，临时修改的上下文设置会恢复；
在明确保存/重试的场景中可能请求已有配置的 Agent Card。

设备测试应手动安装应用与测试 APK 后用 `am instrument` 运行，不在已配置用户数据的手机上运行
会卸载目标应用的 Gradle connected-test 流程。
